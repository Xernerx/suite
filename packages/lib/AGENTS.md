# `packages/lib` (`@xernerx/lib`) — Agent Guidelines (`AGENTS.md`)

## 🧭 Overview

`@xernerx/lib` is the core shared logic, Mongoose database schema registry, NextAuth configuration, localization dictionary store, navigation registry, and shared Next.js configuration package for the Xernerx Suite.

## 📦 Subpath Exports & Architecture

- **`@xernerx/lib` (`./index.ts` — Client-Safe):**
    - `auth`, `navigation`, `proxy`, `env`, `products`, `permissions`, `timezones`.
- **`@xernerx/lib/server` (`./server.ts` — Server-Only, guarded by `import 'server-only'`):**
    - `database`: MongoDB/Mongoose connection manager (`database.connect()`).
    - `registry`: All Mongoose models (`Bots`, `Core`, `Dispatch`, `Guilds`, `Organizations`, `Users`, `Virtue`, `Media`, `Tokens`, etc.).
    - `dictionary`: Server-side locale loader.
    - `dispatch`: Email (Postmark) and webhook dispatching helpers.
    - `themeLayout` & `BasicTemplate` (React Email).
- **`@xernerx/lib/core` (`./core.ts`):**
    - Re-exports `dictionary`, `database`, and `registry` for backend services (`services/bot`, `services/websocket`).
- **`@xernerx/lib/next.config` (`./next.config.ts`):**
    - `withXernerxConfig(config)`: Shared Next.js wrapper configuring `reactCompiler: true`, SVGR loaders, `transpilePackages`, image remote patterns, and `/discord` / `/support` redirects.

## ⚠️ Critical Rules & Gotchas

1. **Strict Client/Server Separation:**
    - **NEVER** import from `@xernerx/lib/server` or `src/models/*` inside any client component (`'use client'`) or re-export server modules from `./index.ts`.
2. **Dictionaries & `i18n.config.ts`:**
    - Localization JSON files live in `src/dictionaries/*.json` (`en-GB.json` is the primary source of truth).
    - **Delete Stale Translations on Key Updates:** Whenever an existing key in `src/dictionaries/en-GB.json` is updated or removed, you **must** delete that same key path from all other language files (`src/dictionaries/*.json` excluding `en-GB.json`) so they fall back to the new `en-GB.json` string and resurface for re-translation in the Admin portal.
    - **NEVER manually edit `src/i18n.config.ts`**—it is automatically generated by `pnpm suite generate-locales`.
3. **Mongoose Model Registration:**
    - When adding or modifying schemas in `src/models/*`, always use `mongoose.models.<Name> || mongoose.model(<Name>, schema)` to prevent hot-reload model overwrite errors in Next.js, and export the model through `src/registry.ts`.
